# Sibionics 2 Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Sibionics 2 as a selectable xDripSwift CGM, connect over BLE, validate and process V120 readings, and deliver live/history data through the existing CGM pipeline.

**Architecture:** Keep packet parsing, handshake sequencing, and the Sibionics 2 stock processor deterministic and unit-testable. A `BluetoothTransmitter` subclass owns only sensor-specific callbacks and delegates scan/connection/reconnect to the existing base; persisted type registration routes readings through the existing `CGMTransmitterDelegate` pipeline.

**Tech Stack:** Swift, CoreBluetooth, Core Data lightweight migration, XCTest, Xcode project file references, GitHub Actions, Fastlane.

**Spec:** `docs/superpowers/specs/2026-09-26-sibionics2-design.md`

## Global Constraints

- Implement only Sibionics 2 using the V120 path: service `FF30`, notify characteristic `FF31`, write characteristic `FF32`.
- Implement only authentication, activation, time synchronization, data request, and reading reception; do not add reset or maintenance commands.
- Reuse `BluetoothTransmitter`, `CGMTransmitter`, and `CGMTransmitterDelegate`; do not create another central-manager owner or a parallel reading store.
- Keep sensor index and event timestamps, suppress duplicates across reconnects, and request protocol-supported history.
- Add a new Core Data model version after `xdrip v32.xcdatamodel`; preserve existing stores with lightweight migration.
- Use iGlucco to understand behavior and write independent code because its repository has no explicit license. Adapted Juggluco code and fixtures must retain GPL-3.0 attribution and notices.
- Exclude Sibionics GS1, Chinese legacy, GS3, alternate experimental algorithms, reset controls, branch merge, and running the TestFlight workflow.
- The manual direct-build workflow must build the selected ref. Hardware connection and displayed values remain unverified until the user tests a real sensor through TestFlight.

## Review Focus

- Corrupt, truncated, or unknown V120 frames must never advance the handshake or create readings; pin with `testPacketDecoderRejectsCorruptedChecksumAndTruncation` in Task 1.
- Another device or Sibionics variant exposing FF30 must not be adopted as Sibionics 2; pin with `testOnlySibionics2AdvertisementNamesMatch` in Task 1 and the first-connect test in Task 3.
- Replayed indexes and a sensor-session index reset must not duplicate readings or reuse stale processor state; pin with the reconnect and reset tests in Task 3.
- Warm-up and invalid raw values must not be published as verified glucose; pin with the V116A fixture and invalid-input tests in Task 2.
- Existing v32 Core Data stores must keep their saved peripherals after migration; pin with `testV32PersistentStoreLightweightMigratesAndKeepsExistingRecords` in Task 3.

**Interfaces:**
- `Sibionics2ProtocolCodec` exposes `serviceUUID`, `notifyUUID`, `writeUUID`, `deriveSessionKey() -> Data?`, `encrypt(_ data: Data) -> Data`, `decrypt(_ data: Data) -> Data`, `parseV120(_ data: Data) -> Sibionics2ParseResult`, `buildAuthPacket(macAddress: [UInt8], sessionKey: Data) -> Data`, `buildActivationPacket(at: Date) -> Data`, `buildTimeSyncPacket(at: Date) -> Data`, and `buildDataRequestPacket(lastIndex: UInt16) -> Data`.

When CoreBluetooth cannot expose a MAC address, pass six zero bytes for auth, as documented by the reference implementation.
